## 1. 产品概述

| 项 | 内容 |
|---|---|
| 游戏名 | 玉兔:破阵 (Jade Rabbit: Warsong) |
| 一句话定位 | 中国古风、拟人动物题材的节奏动作 Roguelike |
| 核心融合 | 《Hades》式流畅近战连招 + 节奏音游的拍点判定 |
| 世界观 | 中国古代朝廷背景，拟人化动物角色，主角为兔子武侠 |
| 视角 | 2:1 等距视角（3D 场景，URP 渲染） |
| 平台 | PC（Windows / macOS），完整手柄支持 |
| 定价对标 | $19.99 |
| 团队与周期（v1 计划） | 4 人核心团队，12 个月首版 |

### 1.1 差异化卖点

与竞品的核心差异（v1 PRD 竞品分析结论）：

| 维度 | 死亡细胞 | Hades | 本作 |
|---|---|---|---|
| 战斗核心 | 装备 Build | 祝福组合 | 节奏连招 |
| 题材 | 西式暗黑 | 希腊神话 | 中国古风 + 拟人动物 |
| 成长 | 图纸解锁 | 镜子升级 | 心法修炼（局内）+ 功勋（局外） |

### 1.2 目标用户（v1 PRD 用户画像）

- 硬核动作玩家（35%）：追求连招精度，常参与速通挑战，需要深度连招系统和精确判定反馈
- 国风文化爱好者（30%）：被美术风格与题材吸引
- Roguelike 玩家（25%）：追求构筑多样性与重复可玩性

### 1.3 成功指标（v1 PRD）

- 30 日留存 25%
- Steam 好评率 > 80%
- 动作 Roguelike 品类年增长约 18%（市场依据）

## 2. 核心玩法循环

### 2.1 局内循环（单局约 20 到 30 分钟）

进入地牢 → 逐房间战斗（踩节拍攻击获得伤害与连击加成）→ 房间奖励（心法三选一等）→ 精英/事件房 → Boss 战（阶段化节奏变化）→ 结算（功勋转化）

### 2.2 局外循环

功勋（永久货币）→ 修炼永久升级（血量/攻击/冲刺 CD 等倍率）→ 解锁新武器与心法池 → 下一局强度与构筑广度提升

### 2.3 节奏层与动作层的关系（本作独有）

- BGM 以固定 BPM 驱动全局拍点时钟（Conductor）
- 玩家任意攻击输入都会被判定与最近拍点的偏差，给出 Perfect / Good / Miss 分级
- 判定结果反馈到：伤害倍率、连击数、特效表现，以及部分敌人技能的触发条件
- 敌人（尤其 Boss）的攻击遵循节拍前摇，玩家可预读

## 3. 功能需求

优先级：P0 为首发必需，P1 为首发目标，P2 为后续版本。
v1 验证状态图例：[已验证] 原型跑通、[部分] 有实现但不完整、[未实现] 纸面设计。

### F1 武器与连招系统（P0）[部分]

需求：
1. 首发 3 种武器：苗刀（MiaoDao）、长枪（Qiang）、剑（Sword），每种武器有独立的轻击（X）、重击（Y）、冲刺攻击三类动作与连招树
2. 连招树用 ScriptableObject 数据驱动，支持轻重交替连段（如 X-X-Y）
3. 每段攻击有独立参数：伤害倍率、位移倍率、持续时间、后摇（backswing）、连段重置时间
4. 输入判定精度 ±3 帧（60FPS 下 50ms），支持连招输入缓冲
5. 连招表示例（苗刀，v1 PRD 定义）：

| 连招 | 伤害倍率 | 特效 |
|---|---|---|
| X-X-X | 1.2 × 3 | 第三击破防 |
| X-Y | 1.5 + 2.0 | 击退 |
| Y-Y | 2.5 × 2 | 消耗气力，霸体 |

v1 验证结论：
- 苗刀完整实现（模型/动画/数据/连招），长枪仅数据（QiangSO），剑未开始
- SO 驱动连招参数的思路已验证可行（WeaponSO 基类 + 每武器子类）
- 教训：连段状态转移在 MiaoDaoSO/QiangSO 里用 if-else 硬编码，两把武器代码几乎重复。v2 升级为数据化连招图 + 取消窗模型，动画由 Animancer 代码驱动（见 docs/06 第 3 节）

### F2 节奏战斗（P0）[已验证核心]

需求：
1. Conductor 式 DSP 时钟：`songPosition / songPositionInBeats / secPerBeat`，不依赖帧率
2. 判定分级与加成（v1 PRD 目标值）：
   - Perfect（±0.05s）：120% 伤害
   - Good（±0.1s）：110% 伤害
   - Miss：正常伤害，无加成
3. 连击系统：Perfect/Good +2、Pass +1，超时未操作重置（v1 为 2 秒）
4. 敌人攻击带节奏前摇提示；完美时机可触发暴击或格挡
5. 全局节奏可视化：屏幕边缘脉冲、音符 UI、准星（AimBead）随拍闪烁
6. 判定反馈视觉语言（v1 前端规范）：Perfect 金光编钟、Good 橙纹木鱼、Miss 灰碎丝弦；判定需返回 early/late 方向供教学提示
7. 延迟校准（v2 新增 P0）：提供音频/输入延迟校准流程（首次进入 + 设置页），判定一律使用校准后时间；校准值随存档保存
8. 实现模型（v2 设计决策）：攻击采用「量化到拍网格执行 + 按输入偏差评级」的混合模型，移动/闪避保持即时；M2 以三档配置试玩定案，详见 docs/06 第 1 节

v1 验证结论：
- DSP 拍点时钟、四级判定窗（v1 实现为 0.12 / 0.30 / 0.45 拍，窗口互相嵌套）、连击 UI、音符生成已跑通
- 教训：判定窗以「拍」为单位实现，与 PRD 以「秒」为单位的定义不一致，v2 需统一；RhythmManager 被战斗与 Boss AI 直接静态调用，耦合过重（见重构建议 D5）

### F3 敌人与 Boss（P0）[部分]

需求：
1. 普通敌人：巡逻 / 发现追击 / 近战攻击 / 眩晕受击，基于 NavMesh 寻路，行为参数（攻击间隔随机区间等）由 EnemyInfoSO 配置
2. Boss：行为优先级 眩晕 > 技能二 > 技能一 > 近战 > 追击 > 巡逻，技能触发可与拍点绑定
3. Boss 阶段化节奏设计（v1 PRD）：随血量阶段切换拍号 4/4 → 3/4 → 5/8；3 次完美格挡触发处决 QTE
4. 首发 Boss 题材参考：乌鸦 Boss（用苗刀重击破防的设计场景）
5. 敌人出手节奏化（v2 设计决策）：所有敌人攻击经战斗导演（攻击令牌 + 拍槽）量化落拍，前摇时长以拍为单位，保证「听音乐防御」成立，详见 docs/06 第 4 节

v1 验证结论：
- 敌人 AI 迭代了三代：Observer 版 → 分层状态机（AISM v3）→ 自研行为树（AIBT v1，Boss1BT/Boss2BT 落地）
- 行为树 + 黑板 + 传感器（SphereCollider 触发器）方案已验证；阶段化拍号切换与 QTE 未实现
- 教训：三套方案并存从未收敛；商业插件 Behavior Designer 已购入但零使用（见重构建议 D2）

### F4 随机地牢生成（P0）[未实现]

需求（v1 PRD）：
1. 预设房间池 + 随机拼接，首尾房间固定（入口/Boss）
2. JSON/SO 配置房间类型权重：combat 0.6 / event 0.3 / 其他 0.1
3. 关键路径长度 5±1 房间
4. 原技术设想：BSP 树 + 波函数坍缩（WFC）

v2 建议：MVP 先做「手工房间 + 线性拼接 + 权重抽取」，BSP/WFC 推迟到内容期（见路线图 M4）。

### F5 Roguelike 成长（P0）[未实现]

需求（v1 PRD）：
1. 局内「心法」：房间奖励三选一的临时强化，稀有度 普通 70% / 稀有 25% / 传说 5%
2. 局外「功勋」：永久货币，升级成本 = base × 1.5^(level-1)
3. 永久升级维度（v1 PlayerInfoSO 已定义字段）：HP 倍率、攻击倍率、冲刺 CD 倍率、武器解锁、各武器最高连段解锁

v1 验证结论：数据容器（PlayerInfoSO/PlayerStatusSO 双 SO：局外持久 + 局内运行态）与存档链路已就绪，玩法层未实现。

### F6 角色与叙事（P1）[未实现]

需求：
1. 拟人动物 NPC，2D 立绘 + 3D 模型结合，等距视角演出
2. 对话系统承载剧情与商店/事件交互（v1 已引入 Pixel Crushers Dialogue System，未接线）
3. P2：剧情分支

### F7 存档（P0）[已验证]

需求：
1. 多档位（profile）、自动存档、场景加载时自动分发数据
2. JSON 序列化 + 加密（v1 PRD 目标 AES-256；v1 实现为异或混淆）+ .bak 备份回滚
3. 存档内容：玩家成长数据（PlayerInfo）、死亡次数、货币等

### F8 UI / HUD（P0）[部分]

需求：
1. 战斗 HUD：血量、连击数、节奏指示器（音符轨道 + 判定准星）、当前武器
2. 局内地图：水墨风格
3. 视觉规范（v1 前端规范）：主色 绛红 #9E2F2C、石青 #1685A9、金 #FFD700；字体 汉仪尚巍手书（标题）+ 思源宋体（正文），注意字体商用授权
4. 手柄导航完整适配

### F9 音频（P0）[部分]

需求：
1. BGM 即玩法：每首关卡曲目需标定 BPM 与偏移，驱动 Conductor
2. 判定音效分级反馈（编钟/木鱼/丝弦）
3. v1 PRD 设想 FMOD + Timeline；v1 实际用 Unity AudioSource + DSP 时间已够原型用。v2 决策见重构建议 D6
4. v1 测试曲目：大闹黑风山.mp3（版权曲目，正式版需替换为原创/授权音乐）

### P2 次要功能（后续版本）

联机排行榜、皮肤付费、Boss Rush 模式、剧情分支。

## 5. MVP 定义（v2 重启的第一个可玩版本）

一局完整可玩的最小垂直切片：

1. 苗刀 1 把武器，完整轻/重/冲刺连招 + 节奏判定加成
2. 普通敌人 1 种 + Boss 1 个（行为树驱动）
3. 手工拼接 3 到 5 个房间的线性关卡（入口 → 战斗 ×2 → 奖励 → Boss）
4. 心法三选一（3 到 5 个心法效果）
5. 死亡/通关结算 + 功勋累积 + 1 项局外升级
6. 存档、暂停、基础 HUD

MVP 不含：第二三武器、随机地牢算法、对话叙事、多 Boss、皮肤/排行榜。

## 6. 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 节奏与动作手感融合失败（核心假设风险） | 高 | M1 结束即做外部试玩验证「踩拍攻击是否有趣」，不达标先调玩法再扩内容 |
| 范围失控（v1 教训：三套 AI、两套角色架构并存） | 高 | 每个系统只保留一条技术路线，架构决策见 03 文档，未决策不动工 |
| 美术产能不足（v1 美术资源基本空缺） | 中 | MVP 全程用代理资源/白盒，美术风格验证独立推进 |
| 第三方资产与音乐授权（v1 插件来自资源分享站、BGM 为版权曲目） | 中 | 商用前全部替换为正版授权，见 03 文档 D3 与合规清单 |
| 单机原型阶段过度设计后端（v1 曾规划微服务后端） | 低 | v2 首发纯单机，排行榜等后端需求推迟到 P2 |
